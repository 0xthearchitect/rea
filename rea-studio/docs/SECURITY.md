# Security model

Imported targets and REA output are untrusted data. Studio exposes deterministic static JavaScript analysis and a closed set of existing native inspection operations; import and analysis never execute the selected target. Native providers may start analysis processes, use their existing configured transports, and write ephemeral analysis data under REA's lifecycle. REA and Studio run with the user's OS permissions, not a security sandbox. Do not assume static inspection makes an artifact safe to execute.

Native dialogs select target and dependency paths. The frontend has no filesystem or shell plugin permissions. The host invokes an absolute trusted Node binary with argument arrays; no shell strings or arbitrary REA tool names are accepted. No local HTTP API is exposed. The production CSP restricts scripts, worker, font, image, and IPC sources to local resources. External HTML is never rendered; output appears as escaped text or in a read-only editor. Commercial engines are not bundled.

Source navigation accepts exact relative paths without traversal, resolves them inside the selected directory, bounds bytes before allocation, and checks the read content against REA's recorded SHA-256 before returning text. Source files changed after analysis are rejected. ASAR extraction is delegated to REA and is not exposed through Studio. JSON indexing has explicit file/message/row/view bounds.

Native task requests are typed and restricted to overview, function search, strings, function dossiers, instruction reads, address inspection, and references. Provider IDs and queries retain their caller values. Target-specific availability is checked after opening; no operation is enabled merely by its catalog name. Ghidra/IDA/Hopper are configured and supervised by the existing REA implementation. Studio adds no annotations, provider database save/close, or target mutation operation; `close_binary` releases the owning REA session according to the provider's existing contract. Pseudocode is displayed as decompiler-generated text. Schema 1 workspaces are backed up consistently before the additive schema 2 migration.

The original Evidence bundle retains caller-selected paths, digests, parameters, IDs, and outputs without inferring secrecy from names. Studio does not serialize the ambient environment. Authentication credentials should be redacted by their owning transport; this MVP has no authenticated remote transport. Exported target data can still be sensitive and should be handled under the user's own access policy.

Project deletion requires a native confirmation, validates Studio-owned UUID directories against the application store, and preserves target files. Exports require a new caller-selected path and refuse to overwrite existing files. Failed cleanup remains reported. Cancellation does not establish provider cleanup merely because the client promise ended. Windows ACLs follow the per-user app-data directory; Unix data-root permissions are narrowed to the owner.

The `e2e` build feature enables an isolated test-data override and fixed self-owned file-dialog selection. Only verification builds enable it; production builds ignore those environment overrides. Debug WebView endpoints are used only by the native E2E runner, never normal application launch.

A retained native session is reused only after streaming SHA-256 validation and exact target/provider selection checks. Target bytes are checked again before indexing. Delete confirmation is followed by a second active-job check under the admission lock, covering jobs started while the dialog was open. Exports validate and retain their source before creating a new destination and preserve exact selected path values.

Agent questions use a trusted caller-selected Codex executable with discrete arguments and a read-only scoped app-server thread. Static dynamic tool handlers are the only investigation routes supplied by Studio; they bind target/provider/output choices outside model arguments. Other MCP registrations, plugins, skills, shell/snapshots, browser/computer actions and image tools are disabled for the thread. Unknown server requests receive no approval. No bypass-permissions flag is used. The installed client owns authentication; Studio never asks for or stores API keys.

Model questions, completed conversation text and explicitly attached facts leave the machine according to that client/provider's policy. This is visible in the composer and context preview. Target text is untrusted and grants no authority. Assistant prose has analyst-inference authority, while original REA records retain their own provenance. Linking a produced Evidence ID does not verify every free-form claim in an answer. Agent context cannot attach another project's job. Schema 2 workspaces receive an idempotent consistent backup before schema 3; interrupted turns retain partial answers and already exported/indexed Evidence.

Agent Markdown is parsed for presentation with raw HTML escaped. Model-supplied links and images render as inert text and do not navigate or fetch remote resources. Only the host-owned original-Evidence buttons select saved result identities; model prose cannot choose a job to open. Clipboard failures remain visible, with code still available for manual selection. The complete original answer stays in SQLite independently of presentation.
